# 0.0.1 单元测试

用例来源是 `spec/0.0.1/test.md`。测试类及参数用例的名称保留文档编号，完整网格使用 `cells[y][x]`，坐标范围是 `0..126`。

- `GameSessionTest`：37 个用例，覆盖 SNAP、STEP、START、PAUSE、RESET、CLEAR 的全部编号。每个用例独立创建模型替身和手动定时器；不依赖模型规则实现、单元格编辑接口或 libGDX 图形环境。
- `LifeModelTest`：43 个用例，覆盖 MODEL 的全部编号，包含 18 组中心规则、9 组孤立格、4 组角落和 4 组边界数据。除文档指定的中心规则断言外，均比较完整的 127 × 127 网格。
- `ManualSchedulerTest`：4 个用例，验证测试定时器的到期执行、取消、重新计时和执行顺序。

运行：

```powershell
.\gradlew.bat :core:test
```

目前仅定义模块接口，业务实现尚未编写。`support/TestSubjects.java` 的三个工厂方法是后续实现的接入点，当前主动抛出带说明的断言错误。因此预期结果是 80 个业务契约用例失败、4 个定时器用例通过；业务用例没有被跳过，也没有用测试替身代替真实的被测实现。

实现模型和会话后，仅需在这三个接入点构造真实对象。`modelWithState` 应直接准备当前状态和上次编辑状态，可以使用实现包内的测试夹具；不应依赖尚未定义的用户编辑指令。生产接口无需为测试增加单元格编辑或任意状态替换入口。

定时器接口是会话的可注入依赖，手动定时器同时承担测试时钟和到期任务执行。后续 libGDX 适配器应在游戏线程串行调用；当前不需要真实等待或额外线程。

本轮范围对应当前测试文档中的会话与模型用例。显示、拖动、按钮状态、单元格点击和美术要求尚无对应单元测试定义。
